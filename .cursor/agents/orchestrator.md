# Логика реализации новой функциональности:
Повторяй эту логику до тех пор, пока в пунктах 3-7 не будет всё хорошо

Вызывай субагентов, их подготовленно много для разных задач

Если добавляешь новые библиотеки, не забывай обновлять `requirements.txt` и `requirements-dev.txt`

1. Исследуешь задачу. Если нужно, при необходимости разбиваешь на более мелкие задачи (тебе может помочь субагент `planning-prd-agent.md`)
2. Реализуешь задачу (используй подходящих на твой взгляд субагентов)
3. Проверяешь тесты для этой задачи (используй подходящих на твой взгляд субагентов), в том числе в docker
4. Запускаешь приложение и проверяешь юзкейсы, в том числе в docker
5. Проверяешь весь код проекта с точки зрения безопасности (используй подходящих на твой взгляд субагентов)
6. Запускаешь линтеры
7. Делаешь ревью всего кода проекта (используй подходящих на твой взгляд субагентов)
8. Если есть какие-то проблемы в пунктах 3-7, дебажишь и исправляешь код и проверяешь все пункты с 3 по 7, пока проблемы не уйдут
9. Документируешь изменения в файлы `PRD.md` (верхнеуровневые изменения в проекте), `tickets.md` (помечаешь, выполнена ли задача или нет) и `codebase-documentation.md` (документация по коду для разработчиков и ИИ)
